# 014 — Pages / Content: самостійні записи

> **Статус: `done` (2026-11-27, підтверджено автором після рев'ю й recheck).** Етапи 1, 2a–2d, 3–6 виконано; рішення —
> MASTER_PLAN C-99…C-112. Нижче «UX-правки автора» — хронологія; **актуальна поведінка — у розділі «Зведення» і
> в C-108…C-112** (де хронологічний запис суперечить зведенню, правий — зведення).

Розробник оголошує типи записів (блог, вакансії) у `cms.content.ts` свого проєкту і отримує для них той
самий Draft / Publish / Revisions / Lock / переклад, що й для сторінок, без змін Core.

## Що зроблено

**Етап 1 — документи (`20261124100000_cms_documents.sql`).**
- `cms_documents` — спільна identity документа; `cms_pages` — підтип. Вміст (draft, published,
  revisions, locks, fields) посилається на документ. Документ створює й видаляє тригер підтипу.
- PostgREST-embed'и сторінок ідуть через документ (`document:cms_documents!inner(page:cms_pages!inner(key))`).

**Етап 2a — записи (`20261125100000_cms_entries.sql`).**
- `cms_entries` — другий підтип; тип і id незмінні; один UUID не належить сторінці й запису водночас.
- RPC запису: create, lock, get_editable, locale_states, save_draft, publish, restore. Кожна перевіряє
  право й пару (type, id).
- Create: id обирає клієнт (ключ ідемпотентності — повтор не створює дубліката й не віддає токен іншої
  сесії); Content створює з lock, Pages — без.
- RLS: публіка бачить лише опублікований, не архівний запис активною мовою; політики не посилаються
  одна на одну (definer-хелпери з boolean).

**Етап 2b — адреси (`20261126100000_cms_entry_slugs.sql`).**
- Опубліковані slug у `cms_entry_slugs`; ефективний slug мови = власний або slug оригіналу.
- Унікальність фактичного URL на (тип, мова) з fallback, прихованими мовами й архівом; перевірка в
  спільному Publish під advisory lock на тип; `cms_entry_slug_check`, `cms_entry_find`.

**Етап 2c — керування (`20261127100000_cms_entries_manage.sql`).**
- Archive / Unarchive, ручний порядок (повний список з версією), список адмінки, статус вибраних записів.
- Використаний файл не видаляється (C-77, рішення автора): usage враховує записи.

**Етап 2d — реєстрація й repository.**
- `cms.content.ts` (`defineCmsContent` з `nuxt-cms-core/config`): `pages` і `types`. Резолвер
  `src/content.ts` відкидає невалідне з попередженням; build-перевірки маршрутів у `pages:resolved`
  (немає сторінки, два типи на route, немає файла редактора, оголошений path без сторінки) валять build.
- Шаблони модуля: `#cms/content` (серіалізовано, без шляхів редакторів), `#cms/content-editors` (lazy
  import на тип, лише для адмінки; *прибрано разом з `editor`, див. «Форма лише зі схеми»*), тип `CmsEntryTypeKey` з ключів декларації.
- `entries.repository.ts`, типи `nuxt-cms-core/types` (`CmsEntry*`); release lock при закритті вкладки —
  спільний `app/data/unload-release.ts` (сторінки теж).
- Карта помилок клієнта: `CMSSL` → `slug_taken` («Адреса вже зайнята»), `CMSMU` → `media_in_use`.

**Етап 3 — публічні читання (`20261128100000_cms_entries_public.sql`).**
- `cms_entry_get_localized` (запис за адресою мови, переклад, media, адреси всіх активних мов) і
  `cms_entries_get_published` (сторінка типу або вибрані id у їхньому порядку, media, total). Invoker, для anon і
  authenticated; **явний фільтр у тілі** (опубліковано в оригіналі, не архів, активна мова), тож
  залогінений редактор на сайті бачить те саме, що анонім.
- `useCmsEntry(type, { slug, locale? })`, `useCmsEntries(type, query)`, `cmsEntrySelection(value, { limit })`;
  тип — union ключів `cms.content.ts`. SSR через `useAsyncData`, браузер не перечитує.
- `<CmsEntries :entries>`: слот на кожен запис, усередині `CMS_EDITOR = null` і media запису.
- **Ізоляція полів (рішення автора, §7: «слот + строгий Edit Mode»).** Поля записів у `<CmsEntries>` —
  публічний рендер. Поза слотом editable-гілка порівнює свій `:value` з документом сторінки за адресою
  (з дефолтами колекцій і перекладом): інше значення — поле read-only, без вибору й панелі, Engine відмовляє в
  записі адреси, яку тримають лише такі поля; у dev — помилка в консолі.
- Playground: тип `post`, `/blog`, `/blog/[slug]` (404 для невідомої й старої адреси — redirects поза V1, hreflang,
  noindex без перекладу), секція «From the blog» на `/`, демо-пости в `seed.sql`.

**Етап 4 — Pages і Edit Mode записів із маршрутом.**
- Хост редактора `app/editor/host.ts` (Engine, view, UI, сесія, lock lifetime) — і для Edit Mode, і для модалки 5.
- `app/editor/document-repository.ts`: Engine говорить з репозиторієм сторінок або записів (тип, id), ціль
  задає перша прив'язка — `useCmsPage` чи `useCmsEntry` (`bindEntry` у контексті редактора).
- **Ідентичність — UUID.** `/admin/edit/<route зі slug>?entry=<id>`: запис і тип перевіряються за id (чужий тип —
  «не знайдено»), маршрут — за записом маршруту типу; застарілий slug → `replace` на канонічний; без `?entry` —
  пошук серед опублікованих адрес. Сторінка Edit Mode ключується за id (`definePageMeta({ key })`; без цього Nuxt
  перемонтовував її за шляхом — новий Engine і другий lock, знайдено на браузерній перевірці). Після
  збереження / публікації / Restore нового slug шлях оновлюється без нової сесії.
- Рядок «Адреса» під тулбаром (`EntryAddressBar`): поле `slug` документа (Undo, переклад, History), лічильник,
  формат, зарезервовані адреси (статичні сусіди), зайнята адреса (`cms_entry_slug_check`), попередження «стара
  адреса перестане працювати».
- Адмінка: `/admin/pages` (оголошені + відомі БД сторінки зі статусом; типи з route), `/admin/pages/[type]` (пошук,
  архів, пагінація, Archive / Unarchive з «Скасувати», Edit за id), діалог Create (назва → адреса з
  транслітерацією, `app/admin/slug.ts`; id один на відкриття діалогу; без lock). Сайдбар Pages, переклади en / uk.
- Міграція `20261129100000_cms_entries_admin_list_updated.sql`: «Оновлено» у списку — остання публікація чи
  збереження, не створення рядка.

**Етап 5 — Content: модалка й поля Client.**
- `/admin/content` (типи без route) і `/admin/content/[type]`: пошук, архів, Archive / Unarchive з «Скасувати»;
  для `order: 'manual'` — увесь список (до 500), перетягування й кнопки вгору / вниз (клавіатура, mobile).
  Порядок зберігається одразу (`cms_entry_reorder` з версією); застарілий список — тост «Список змінився» і
  перечитування, чужий порядок не перезаписується. Пункт сайдбару Content — лише коли є такі типи.
- Модалка `app/editor/EntryDialog.vue` / `EntryDialogBody.vue` на хості Edit Mode: той самий Engine (Draft / Publish,
  Undo / Redo, validation з фокусом, переклад, History / Restore, lock з heartbeat і release). Перемикач мови,
  lock-банер, статус; Esc спершу знімає виділення поля, Cmd+S / Cmd+Z. Deep link `?entry=<id>`, New — `?create=1`.
- Шар редактора `EDITOR_LAYER`: Overlay, панелі, History, тости й підтвердження телепортуються в модальний
  `<dialog>` (інакше вони в inert-частині сторінки під top layer).
- **Новий запис — лише в пам'яті** (`app/editor/pending.ts`): перший Save / Publish викликає `cms_entry_create` з
  lock (id один на відкриття модалки — повтор ідемпотентний), далі — звичайні save / publish з токеном create, без
  другого acquire. Закрита модалка без збереження нічого не лишає.
- *(Прибрано зміною «Форма лише зі схеми»; історія етапу 5.)* Поля Client: `useCmsEntryField(address, { label, required, maxLength, translatable })` з явного входу
  `nuxt-cms-core/editor` (не auto-import: Editor-код лише в admin-only редакторі, C-21) → `value`, `error`,
  `readonly`, `original`, `ref` для звичайних `<input>` / `<select>` (види полів `input` / `value`; вибір — структура,
  у перекладі read-only). Rich text, зображення, лінк — наявні primitives з `:value` з `content`.
- Медіатека: для використаного файла кнопки «Видалити» немає, замість неї пояснення; використання показує записи
  («Вакансії · «Назва» (чернетка)»).
- **Тексти, що називають тип** — повністю від Client, без склеювання слів у Core (граматика різна в мовах):
  `text: { newButton, newTitle, editTitle }` типу в `cms.content.ts`, кожен — рядок або `{ en, uk }`, у `editTitle`
  підстановка `{title}` (назва запису). Кнопка створення (Pages, Content, списки), заголовок діалогу Create (Pages) і
  модалки (Content). Без них — слова Core: «New», «New entry — Vacancies», «Vacancies — {title}». Дії Core (Save,
  Publish, Archive…) Client не перевизначає. Невалідний `text` (порожній рядок, невідомий ключ) валить build.
- *(Прибрано разом з `editor`.)* Компонент редактора Client отримував `content` і `adminLocale` (мова адмінки) — для власних підписів полів; `label` у
  `useCmsEntryField` можна задати getter'ом. Core не перекладає поля Client.
- У модалці немає пунктирних рамок полів Edit Mode (`OverlayLayer :outlines="false"`): лишаються hover і виділення,
  рамки дає форма Client. Mobile: діалог майже на всю ширину, Save — іконкою, тулбар в один рядок, статус під ним.
- Тости адмінки й редактора: однакове повідомлення (текст і тон, без дії) не дублюється — показаний тост отримує
  повний час знову.
- Playground (етап 5): тип `vacancy` з власним редактором; після зміни C-103 — схема `fields` (див. вище), `/careers` з `VacancyCard`, вакансії в `seed.sql`;
  `check:bundle` перевіряє `/careers` і маркер форми редактора.

**Зміна C-103 (рішення автора 2026-11-25): форма Content зі схеми полів.** Перший крок — `fields` (7 типів) поруч з
`editor`; другий (того ж дня) — **лише схема**, `editor` прибрано, розширення типів полів після цього зупинено.
- **Контракт** (`src/content-fields.ts`, експорт типів з `nuxt-cms-core/config`): `text`, `textarea`, `email`, `url`,
  `phone`, `number`, `select`, `radio`, `multiselect`, `boolean` (`appearance: 'switch' | 'checkbox'`), `date`, `datetime`,
  `dateRange`, `richText`, `image`, `link`; властивості `label`, `hint`, `required` (крім `boolean`), `width`
  (`full` / `half` / `quarter`), `placeholder`, `default`, `maxLength`, `rows`, `min` / `max`, `options`. Спільна
  функція `fieldValueIssue` перевіряє і `default` на build, і значення у формі. `title` (`text`) обов'язковий.
- **Декларація:** тип Content — лише `fields`; `editor` → помилка build «`editor` is no longer supported…», `route` +
  `fields` — помилка; проблеми полів — `field "тип.поле": …`. Прибрано: `#cms/content-editors`, вхід
  `nuxt-cms-core/editor`, `useCmsEntryField`, `app/editor/client.ts`, `app/editor/entry-field.ts`.
- **Форма Core** (`app/editor/form/`): `EntryForm` (сітка 4 колонки: half — 2, quarter — 1; < 1024 px quarter → half;
  < 768 px — усе full), `FormField` (підпис, помилка, підказка, «Оригінал», «Однаково для всіх мов»), `FormValueField`
  (текст / textarea / email / url / phone / число зі stepper / select), `FormChoiceField` (radio, multiselect, switch /
  checkbox), `FormDateField` (date, dateRange, datetime), `FormImageField` (прев'ю + Replace / Remove; порожнє —
  dropzone із завантаженням у медіатеку і «Вибрати з медіатеки»; alt — у медіатеці), `FormRichTextField`,
  `FormLinkField`. `useFormField` реєструє поле в Engine з `form: true` і `validate`.
- **Кіт адмінки (макети Figma):** `AdminCheckbox`, `AdminRadioGroup`, `AdminSwitch`, `AdminNumberInput`,
  `AdminMultiSelect` (чипи + пошук), `AdminDropzone`, `AdminDatePicker` (`@vuepic/vue-datepicker` 14.0.0, змінні
  `--dp-*` → `--cms-*`, без teleport, локалі `date-fns` `uk` / `enUS`; дата, діапазон, час; Esc з відкритим календарем
  закриває лише календар).
- **Після recheck архітектури (рішення автора):** `date-fns` ^4.4.0 задекларовано в `dependencies` (та сама 4.4.0, що
  в календаря; lockfile змінив лише кореневий запис; пакет Core, встановлений pnpm з `node-linker=isolated` і без
  hoist, резолвить `date-fns/locale` і календар, одна копія `date-fns`). CSS календаря — у `@scope (.cms-admin)` через
  `?cms-admin` і Vite-плагін модуля (`src/admin-css.ts`, тест на реальному CSS бібліотеки): на `/careers`, після
  адмінки й в Edit Mode немає ні `--dp-*` на `:root`, ні правил календаря. Прибрано дублі (`FieldIssueKind` =
  `CmsFieldValueIssue`, `isEmptyFieldValue`), другий слухач `focusout`, мертвий код (`context` хоста, `defineExpose`,
  ключ `cms.editor.form.number`), токени замість px там, де значення збігаються. Спільний composable для інших
  повторів полів не вводили: різниця між компонентами більша за виграш.
- **Відомий компроміс:** календар тягне `@vueuse/core` 14 — друга копія VueUse лише в чанку адмінки (public не зачеплено).
- **Дата й час** (`app/editor/form/datetime.ts`): `datetime` зберігається в UTC; форма показує місцевий час зони
  браузера з UTC offset. День і час вибираються окремо, перетворення — через `Intl`: неіснуючий час (перехід на
  літній) — помилка, повторюваний (перехід на зимовий) — дві кнопки з offset, без мовчазного вибору.
- **Engine:** хук поля `validate(value) → 'required' | 'maxLength' | 'range' | 'format' | 'option' | null`; `pending.ts`
  отримує `initial` — дефолти схеми лише для нового документа. Помилки показуються після виходу з поля або спроби
  Publish (`FORM_ISSUES_SHOWN`), фокус — на першому полі з помилкою.
- **Значення не з `options`** (схему змінили) — «(no longer offered)», Publish заблоковано, значення не очищується.
- **Переклад (C-78):** мовою — `text`, `textarea`, `richText`, текст посилання; решта — структура.
- **TS-тип вмісту:** `CmsEntryContent['vacancy']` з `#cms/content`; усі поля, крім `title`, необов'язкові (старі записи
  можуть їх не мати).
- **Playground:** Vacancies — усі типи полів з різними ширинами й дефолтами; Testimonials — `fields` (замість
  `TestimonialEditor.vue`). `check:bundle`: маркери форми (`entry-form-field`) і календаря (`dp--theme-light`).
- **Перевірено в браузері** (prod-збірка проти spike, сценарії CT-FORM-01…07): новий запис з дефолтами, помилки
  лише після Publish / виходу з поля, усі типи і їхні формати в БД, Undo / Redo switch, DST у Europe/Kyiv (помилка і
  явний вибір), та сама вакансія в America/New_York (показ 21:30 UTC−04:00, UTC без змін після Save), значення не з
  `options`, переклад uk, наявні записи без дефолтів і без чернетки, 390 px; помилок консолі немає.
- **Не зроблено (TODO MASTER_PLAN §3):** точка розширення «власне поле», `file`, галерея, теги, повторювані групи,
  зв'язки, підписи лімітів завантаження.

**UX-правки автора (2026-11-25).**
- Списки записів — один список з усіма записами (прибрані з сайту теж; пізніше показуються як «Чернетка») з фільтрами «Статус» і «Сортування» (далі «Сортування» з UI прибрано) замість
  перемикача «В архіві» (міграція `20261201100000…`: `cms_entries_admin_list` з `archived` = null — усі, `status_filter`;
  у порядку сайту прибрані з сайту — на своєму місці, див. нижче; `slug` — адреса на сайті, коли опубліковано).
- Рядки — таблиця без заголовків (однакові колонки назви, статусу, дати, дій); дати `дд.мм.рррр`; під назвою
  «Відкрити на сайті ↗» / «Ще не на сайті» замість `/blog/…`; в Edit Mode — «Посилання на сторінку» з доменом.
- «+» на Pages і Content відкриває діалог на місці; створення статті не переходить в Edit Mode (тост «Редагувати»), щоб
  можна було додати кілька поспіль; назви й кнопки на цих екранах змінюються з мовою адмінки.
- Вихід з Edit Mode — на екран адмінки, з якого його відкрили (`app/editor/exit.ts`), інакше на огляд.

**UX-правки автора, друге коло (2026-11-25).**
- Фільтр «Статус» — множинний вибір (`?status=draft,changed`), міграція `20261202100000…`: `status_filter text[]`
  (null або порожній масив — усі статуси). «Сортування» з UI прибрано: список у задекларованому порядку (`?sort=` у
  посиланні ще працює). Пошук і фільтр ліворуч, кнопка створення праворуч — спільний `AdminEntryFilters`.
- `AdminSelect` отримав режим `multiple` (`v-model:values`, меню не закривається, позначка ✓) і слот `option` — для
  майбутніх фільтрів; `AdminBadge` + `documentStatusTone` — один вигляд статусу в таблицях і фільтрі.
- Статус «changed» — «Є зміни» / «Has changes». Колонки рядків — subgrid (кнопки біля правого краю, рівно в усіх
  рядках); у списках типів кнопка створення — окрема колонка, однакова ширина. «Прибрати з сайту» — обрамлена червона
  кнопка, «Повернути» — звичайна.
- Модалка Content закривається після «Зберегти чернетку» і «Опублікувати» (завершена дія); результат — тост адмінки
  (власні тости модалки зникли б разом із нею). Cmd/Ctrl+S модалку не закриває: це проміжне збереження.
- Чернетка з неправильним значенням (понад ліміт, формат, діапазон, не з options) не зберігається — фокус на полі й
  тост; порожнє обов'язкове поле чернетці не заважає (`session.save()`). Списки записів вантажать дані лише в
  `onMounted`: раніше читання йшло під час серверного рендеру без сесії, і HTML містив «Щось пішло не так», яке
  зникало після гідрації.
- Ручний порядок: запис, прибраний із сайту, лишається на місці зі зміненим статусом (раніше йшов в кінець, а
  «Повернути» піднімало його нагору). Міграція `20261203100000…`: `cms_entry_reorder` ставить живі записи в «слоти»
  живих і перенумеровує весь список (контракт і версія порядку живих без змін), `cms_entry_unarchive` не чіпає
  `sort_order`, список не відсуває прибрані. У UI прибраний рядок лишає ручку й стрілки неактивними;
  перетягування на нього кладе запис на місце наступного живого (`reorderInPlace` — те саме правило локально до
  відповіді сервера). Стара поведінка (прибрані — останні) змінює рішення §8.1 «Unarchive на початок».
- Шапка сайту в Edit Mode будувала посилання перемикача мови з `/admin/edit/...` → `/uk/admin/edit/...` (попередження
  роутера, клік вів на `/admin/edit/uk/admin/edit/`): playground бере шлях сайту без `/admin/edit`. Правило «чужого
  значення» (`isForeign`): поле без значення (`null`) не може показувати чужі дані, тож шлях обкладинки з коду (поле
  передає `null`) більше не дає хибної помилки `[cms] Field … shows a value that is not this page's`.
- Перемикач мов у модалці є і в нового запису (до першого збереження). Переклад потребує оригіналу, тож перше
  перемикання створює чернетку (`session.save()`); без назви — фокус на поле й тост «Спершу введіть назву…».
- Перемикання мови в модалці не питає «Вийти без збереження?»: набране тихо зберігається як чернетка (без тосту) і
  відкривається інша мова; з неправильним значенням — фокус на полі й тост, мова не міняється; якщо зберегти не
  вийшло (втрачений lock) — тоді запитання як раніше. В Edit Mode сторінок мова міняється через URL, і запитання там
  лишилось.
- Рядок списку записів (Pages і Content): велика «Редагувати» прибрана — запис відкривається кліком по всьому рядку
  (крім кнопок, посилань і керування порядком); біля назви стрілка лише як підказка, завжди видима й не обрізається
  (назва скорочується «…»). У ручному порядку рядок перетягується лише за ручку (за неї ж картинка — весь рядок).
  Одна кнопка дії в колонці (пізніше «Прибрати з сайту» зроблена спокійною: звичайна кнопка, червона лише при наведенні —
  дія оборотна, сильна лише «Опублікувати»; «Повернути» більше немає, див. нижче). Спочатку була заливна: «Опублікувати» (primary) для чернетки, «Прибрати з сайту» (destructive) для
  опублікованого, «Повернути» (secondary) для прибраного. «Опублікувати» зі
  списку не обходить перевірок: у Content відкриває модалку й одразу пробує публікацію (`publishOnOpen`), у Pages —
  Edit Mode з проханням опублікувати в history state переходу (`publishOnOpenState` / `takePublishOnOpen`,
  `app/editor/entry-route.ts`; спершу було `?publish=1` в адресі — прибрано після recheck-рев'ю X-2: чуже посилання
  публікувало б одразу з вимкненим питанням); EditorRoot пробує, коли поля сторінки на екрані; далі
  перевірка полів і питання про публікацію як зазвичай. Прибраний з сайту запис відкривається й редагується як інший (змінює чернетку, лишається знятим, поки його не опублікують; публічно не видно).
  Під час перетягування в ручному порядку рядок-ціль підсвічується фоном і лінією з того боку, куди ляже запис.
- «Опублікувати» зі списку Content тиха: модалка (`AdminDialog` з `silent`) не показується, поки запис
  завантажується й публікується, і з'являється лише коли потрібна людина: питання про публікацію (якщо воно ввімкнене),
  помилка в полі (фокус на поле), чужий lock, або якщо триває довше 2,5 с. Успіх — тост і список оновлено без миготіння.
- Лічильник типу на оглядах Pages і Content («Клієнти (8)») рахує всі записи, прибрані з сайту теж, як довжина списку,
  який відкривається (раніше лише живі — число розходилось зі списком). Підказку про перетягування над списком
  прибрано.
- **Знятий із сайту запис — це чернетка** (рішення автора, 2026-11-27, варіант 2). У списках статус «Прибрано з сайту»
  не показується: такий запис — «Чернетка» з кнопкою «Опублікувати», а не «Повернути»; фільтр «Чернетка» включає й їх
  (`serverStatuses`). Усередині лишається `archived_at` (адреса й остання публікація збережені, місце в порядку теж).
  «Прибрати з сайту» — як було (архів, тост зі «Скасувати»). «Опублікувати» публікує чернетку і повертає запис на сайт
  в одній транзакції (`cms_entry_publish`, міграції `20261204…`, `20261205…`): для оригіналу; переклад запис не
  повертає. Без чернетки (знятий як був) «Опублікувати» повертає запис з тією версією, з якою його зняли; переклад без
  чернетки, як і раніше, відхиляється (`P0002`). `cms_entry_get_editable` повертає `off_site`, Engine (`offSite`)
  показує такий запис як чернетку й дозволяє «Опублікувати» без чернетки; Activity пише `unarchive`.
- **Остаточне видалення запису** (C-108, 2026-11-27): іконка-кошик у модалці Content і в тулбарі Edit Mode (лише запис,
  якого немає на сайті; кнопки в списку немає), підтвердження «Видалити «…» назавжди?». Міграція
  `20261206100000_cms_entry_delete.sql` (`cms_entry_delete`, помилка `CMSEL` → `entry_live`), подія `delete` в
  Activity. Після видалення модалка закривається, Edit Mode веде в список, звідки його відкрили.
- Кнопки запису у вікні редагування (модалка Content і тулбар Edit Mode, 2026-11-27): якщо запис на сайті й нічого
  публікувати, замість «Опублікувати» — «Прибрати з сайту» (міграція `20261207…`, `cms_entry_take_off`: те саме, що
  archive, але під lock цієї сесії; звичайний archive відмовляє, поки запис відкритий); після зняття запис лишається
  відкритим як «Чернетка» з «Опублікувати». Кошик «Видалити» завжди є (за правом `pages.publish`), але вимкнений, коли
  запис на сайті, з підказкою «спершу зніміть із сайту»; дозволений — червоний із підписом (у модалці), щоб його було
  видно.
- Підтвердження публікації: «Опублікувати» питає один раз (`session.publish()`, тож тулбар Edit Mode і модалка Content
  мають те саме вікно): «Опублікувати на сайті? Зміни одразу з'являться на сайті», чекбокс «Більше не питати», фокус на
  «Скасувати». Питає після перевірки полів (помилки спершу ведуть до поля). Прапорець — особисте налаштування в
  `localStorage` (`cms-admin:confirm-publish`, `useConfirmPublish`), без права й без БД; вмикається назад у
  Налаштування → Редагування. «Опублікувати зміни» в Текстах не змінено: там уже є вікно з вибором сторінок.
  У тому ж вікні — попередження, якщо в показаних мовах (активні, не оригінал) бракує перекладу текстів: «Не
  перекладено: Українська (3 поля). Для цих мов на сайті буде оригінал.» (`engine.translationGaps`: за полями, що є
  на екрані — тексти, підписи лінків, alt зображень; переклад відкритої мови — як на екрані, інші — з чернетки чи
  публікації). Публікацію це не блокує, а збій підрахунку не заважає питанню. З «Більше не питати» вікна немає, тож про
  неперекладені мови каже тост після публікації («Опубліковано. Не перекладено: Українська (3 поля). Для цих мов буде
  оригінал.», довгий; у модалці Content — тост адмінки). Рахунок точний лише для того, що на екрані; у списку
  індикатора мов поки немає. Довжина не росте з кількістю мов: до трьох мов — по імені в рядку, більше — «Повністю перекладено
  4 з 10 мов» (основна мова теж рахується) і згорнутий список «Показати мови»; тост після публікації тоді теж лише рахує.
- Модалка: `cancel` від `<input type=file>` (закрите вікно вибору файлу) спливав до `<dialog>` і закривав його —
  `AdminDialog` закривається лише на власний `cancel`. Заголовок діалогу — h2. Перемикач / чекбокс поруч із полями
  стоїть на лінії їхніх контролів. Мультиселект відкривається одним блоком з полем, як `AdminSelect`. Rich text —
  кільце фокуса поля замість подвійного. Посилання — один рядок: текст, адреса, «нова вкладка».
- Іконка в основному слоті `AdminButton` вирівнюється по центру тексту.

- S-1: подія «Прибрано з сайту» в Activity веде в список з фільтром «Чернетка» (`?status=draft`).
- Прибрано мертве: `setArchived(…, false)` → `takeOff`, тон `archived`, ключі `cms.pages.status.archived`,
  `type.unarchive(d)`, `neverEdited`, `type.column*`. Спільні `session.entryName()`, `editorShortcut()` (host),
  іменовані таймаути публікації на відкритті, токени замість px у Checkbox / Radio / MultiSelect / DatePicker.
- Сценарії: дублікати ID перенумеровано (CT-PUB-05/06, CT-PAGES-04), CT-PAGES-02, 07a, 09a, SEL-04, ACT-01 — під
  поточну поведінку.

**Перевірки на кінець:** vitest 688 / 62 файли, pgTAP 753 / 23 файли (після recheck — на ізольованому стеку), typecheck, lint, `check:bundle`; сценарії —

**Відкрите на кінець (не закриває епік саме по собі)**

- «Відкинути зміни» для статусу «Є зміни» (повернутись до опублікованої версії) — немає, див. MASTER_PLAN §3.

- Дозвіл дубльованих `dp` / VueUse 14 залежностей (компроміс A-2) — без змін, у «Обмеженнях V1».
- Тестові дані: усі сценарії видалення, публікації й порядку проганялись на ізольованому стеку (не в робочій БД). У

## Обмеження V1

- **Restore старої ревізії з видаленим файлом.** Ревізії не вважаються використанням (C-72), тож файл,
  який лишився лише в старій версії, можна видалити. Restore такої версії показує в полі зображення з
  коду сайту; Restore і Publish не падають. Окремого захисту файлів ревізій немає (рішення автора).
- `require_slug` (тип із route мусить мати адресу) передає клієнт: реєстру типів у БД немає.
  Унікальність адрес сервер перевіряє завжди.
- Хелпер видимості `cms_document_public` доступний anon (працює в RLS) і за відомим UUID каже, чи
  документ архівний. Вміст не розкриває.
- Строгий Edit Mode: примітив, якому сторінка передає **перетворене** значення (`:value="title || 'x'"`,
  `.toUpperCase()`), у Edit Mode read-only — значення не з документа. Дефолт — через слот (C-47).
- **Демо-пости в робочій БД (додано на етапі 3 без погодження; не видаляти до окремої згоди).** Записи
  `cms_entries` типу `post` і їхні документи, публікації, ревізії, адреси, вставлені з `seed.sql`:
  `b1000000-0000-4000-8000-000000000001` (calm-interfaces), `…0002` (prototype-in-code), `…0003` (small-studio),
  `…0004` (old-news, архів), `…0005` (coming-soon, лише чернетка). `check:bundle` з маршрутами блогу потребує цих
  постів у БД, на якій працює збірка (на чистому стеку їх дає `db reset` із seed).
- **Демо-сайт у робочій БД (2026-11-25, на прохання автора).** Playground отримав сторінки Services, Work, Contact
  (`/services`, `/work`, `/contact`), тип із маршрутом `project` (`/work/[slug]`) і типи Content `member`, `faq`,
  `client`; команда показується на `/about`. Той самий блок даних — у `seed.sql`. У робочу БД додано лише нові рядки
  (наявні не змінено; Activity не змінилась), id за префіксом: `b1…0006–0009` (пости), `d1…0001–0006` (проєкти,
  `0005` — архів, `0006` — чернетка), `c1…0001–0006` (вакансії; `0001–0003` — з seed), `e2…0001–0004` (відгуки),
  `e1…0001–0005` (команда), `f1…0001–0005` (FAQ), `a1…0001–0006` (клієнти); плюс публікації сторінок `careers`,
  `services`, `work` (з неопублікованими змінами), `contact` і рядки `cms_pages` для `services`, `work`, `contact`.
  Медіа не додавалися: поля зображень порожні.
- Дата першої публікації запису в Edit Mode не показується (`firstPublishedAt` у прив'язці — null): editable-читання
  її не повертає.
- Draft-slug, що дорівнює статичному сусіду (`/blog/archive`), у браузері перевірено в G3 (фікстура); у playground
  такого сусіда немає — код резолву за записом маршруту той самий.
- Записи видаленого з декларації типу зникають з адмінки й з читань сайту через composables, але прямий REST /
  RPC за ключем типу їх ще віддає (опубліковане свідомо). Прибрати — Archive перед видаленням типу; DB-реєстр
  типів — поза 014.
- Slug-и перекладів у прихованих мовах видно anon через REST (`cms_entry_slugs`), без вмісту — допустимі
  публічні метадані (рев'ю X-1).
- Схема полів не перевіряється на сервері (SQL її не знає): правила форми тримає Engine. Перейменоване / видалене
  поле лишає старі значення в документах; змінений тип поля показує його порожнім. `default` застосовується лише до
  нового запису.
- Старі тестові події Activity від dblink-тестів до 2a і рядки `cms_form_rate_limits` бакета `total:concurrency`
  (011, до етапу 5) лишаються в робочих БД (очистка — окремо за id). Нові прогони `test:db` нічого не лишають.
- Користувач, який дивиться запис під чужим lock, бачить **опубліковану** версію (як в Edit Mode сторінок): draft —
  незавершена робота власника lock.
- Тексти lock-банера й підтвердження виходу спільні з Edit Mode і кажуть «сторінка» також для запису в модалці.
- Запис, у якого опубліковано лише переклад (оригінал — тільки чернетка), на сайті не показується (публічні читання
  вимагають оригінал), але для RLS він публічний: anon через REST читає цей опублікований переклад
  (`cms_entry_public` — будь-яка активна мова). Розкривається лише те, що редактор сам опублікував; чернетки не видно.
  Такий запис видаляється без кроку «зняти» (CMSEL дивиться на оригінал). Не критично — RLS не вирівнювали
  (recheck-рев'ю X-3).

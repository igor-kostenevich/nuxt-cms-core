# 010b — Переклад усього сайту

Після 010 сторінки перекладались лише в Edit Mode. Двох видів текстів не було ніде:
- тексти з коду сторінки, яких ніхто не редагував: вони живуть у коді (C-42, C-47);
- тексти поза сторінками CMS: меню, футер, тости, повідомлення форм, `<title>`.

Тепер усі тексти зібрано на одному екрані «Тексти». Їх можна змінити й перекласти без розробника.

> *Змінено в 010d* ([запис](./010d-simplify.md)): `cms_page_translate` → `cms_page_set_texts` (оригінал
> теж редагується на «Текстах»), «Опублікувати переклад» публікує вибрані сторінки з перевіркою версії,
> елементи колекцій із коду — за власними id (C-88, C-89). Опис нижче — стан на кінець 010b.

Рішення закрито автором 2026-11-18 → MASTER_PLAN C-84…C-86. Переклад файлом (CSV) — окремий зріз 010c
після 014.

Джерела: Б9 §13, §22; C-63; відгук автора.

## Що зроблено

**Міграція `supabase/migrations/20261119100000_cms_texts.sql`:**
- реєстр полів `cms_page_fields` + `cms_pages.edit_path`; RPC `cms_page_register_fields`;
- тексти сайту `cms_site_texts`:
  - RLS: anon бачить лише активні мови, CMS-користувачі — усі;
  - пише `pages.publish`;
  - RPC `cms_site_texts_for` — мова з fallback на основну, одним запитом;
- `cms_page_translate`: переклад листів сторінки в чернетку поза Edit Mode;
- `cms_language_publish`: публікація чернеток мови на всіх сторінках;
- спільний `cms_page_promote_draft`, на якому тепер стоїть і `cms_page_publish`;
- `cms_language_delete` прибирає й тексти сайту мови.

**Тексти сайту в Client:**
- `cms.texts.ts` з `defineCmsTexts` (`nuxt-cms-core/config`). Модуль вантажить його через c12,
  перевіряє (`src/texts.ts`: ключ — адреса C-48, текст ≤ 2000) і віддає як `#cms/texts`.
- `useCmsText().t(key, params)` (`app/composables/useCmsText.ts`):
  - один запит на мову, SSR;
  - пошук: мова → основна мова → код;
  - `{name}`-підстановка.

**Реєстр полів:**
- поля передають `defaultText` — показаний текст: збережений або дефолт зі slot; для лінка — підпис,
  для зображення — alt;
- `registryEntries` (`app/editor/engine.ts`) бере лише перекладні поля, без фонів і декоративних
  зображень, і збирає приховані `CmsOptional`;
- `EditorRoot` записує реєстр через ~2 с після готовності, лише основною мовою, best effort.

**Edit Mode:** `?field=<адреса>` вибирає поле й прокручує до нього (перехід з екрана «Тексти»).

**Екран `/admin/texts`:**
- пункт «Тексти» в групі «Контент» сайдбару;
- `useAdminTexts`, чиста збірка рядків `app/admin/texts.ts`, `texts.repository.ts`,
  `site-texts.repository.ts`;
- шапка: вибір мови (з прихованими), «Лише неперекладені», «Опублікувати переклад (N)»;
- ліворуч групи з лічильником неперекладених;
- рядок: назва / адреса / контекст → оригінал → поле → ↗ у редактор або «Повернути текст із коду»;
- збереження на blur, тихий ✓, помилки — тостом.

**Спільні правила перекладу:** у `app/primitives/translation.ts` додано `translationLeaf` (який лист
перекладається для kind) і `isTranslatableIn`. Engine і екран користуються одними правилами.

**Playground:** `cms.texts.ts` — меню, кнопка шапки, skip-link, футер, `<title>` сторінок. Layout і
сторінки беруть їх через `useCmsText()`.

**Тести:**
- vitest:
  - `cms-texts.test.ts` (валідація);
  - `admin-texts.test.ts` (оригінал / переклад / неперекладені / дефолтні елементи / групи);
  - реєстр в `editor-engine.test.ts`.
- pgTAP `cms_texts.test.sql`: реєстр (upsert, прибирання, приховані optional, формат, приватність),
  переклад (основна мова, lock, злиття, null, форма), публікація мови, RLS текстів сайту, upsert як
  в API, `cms_site_texts_for`, видалення мови.

## Ключові рішення

**Реєстр, а не копія дефолтів (C-84).**
- Якби Edit Mode писав дефолти в контент, правка розробника в коді після цього вже не з'являлась би.
- Реєстр лише описує, що сторінка показує, і оновлюється при кожному відкритті основною мовою.
- Поля, яких більше немає, прибираються. Поля під прихованим optional лишаються: їх не видно, але з
  коду вони не зникли.

**Тексти сайту — одразу, owner / admin (C-85).**
- Це не контент сторінки з Draft і ревізіями, а короткі рядки інтерфейсу. Чернетка тут — зайва
  складність.
- Тому писати можуть лише ті, хто й так публікує (`pages.publish`).
- Значення по мовах незалежні: зміна основної мови нічого не конвертує.

**Переклад сторінок з екрана — у чернетку (C-86).**
- Той самий шлях, що в Edit Mode: можна перевірити й опублікувати всю мову однією кнопкою.
- Якщо сторінка зараз відкрита в редакторі, переклад відхиляється. Його сесія тримає документ і
  перезаписала б зміну.
- Протермінований lock знімається: стара сесія отримає `lock_lost`.

**Rich text — через ↗.** Повноцінний редактор у таблиці подвоїв би Edit Mode. В оригіналі абзаци
показано окремими рядками.

## Знайдено під час перевірки

- **Upsert давав 403.** PostgREST при `on_conflict` оновлює всі передані колонки, а update було
  дозволено лише на значення. Те саме було в назві сайту по мовах (010), просто її ще не зберігали.
  Права розширено; pgTAP робить upsert так само, як API.
- **Прибирання реєстру спиралось на час** (`seen_at < now()`), а в одній транзакції `now()` не
  змінюється. Тепер прибирається все, чого немає в надісланому списку.
- **Абзаци rich text злипались в оригіналі; елементи колекцій із коду мали порожній оригінал.** Реєстр
  тепер бере показаний текст і пишеться лише основною мовою.

## Після перевірки автором

- **«Спершу збережіть основною мовою» прибрано.**
  - Елемент колекції, який досі є дефолтом із коду, перекладається за id `default-N`.
  - `collectionItems` (`app/primitives/collection.ts`) кладе такий переклад поверх дефолтів
    (`withOverrides`) — і на сайті, і в редакторі.
  - Engine матеріалізує колекцію разом із перекладом, а `canTranslate` / `isTranslatableIn`
    відмовляють лише для елемента, видаленого основною мовою.
  - Тести: `collection.test.ts`, Engine, рядки екрана.
- **Ключі на кшталт `about.body` замінено людськими назвами.**
  - Реєстр запам'ятовує блок сторінки (`data-cms-section` / `aria-label` / перший заголовок
    секції), порядок на сторінці й тег.
  - Екран групує рядки під назвами блоків у порядку сторінки й називає їх «Заголовок», «Текст»,
    «Абзац», «Кнопка», «Посилання», «Опис зображення», «… · елемент N».
  - Текст сайту названо його контекстом.
  - Адреса чи ключ — у підказці при наведенні.
  - Розробник може дати точнішу назву полю через `field-label`, а блоку — через
    `data-cms-section`.
- **Фікстури pgTAP прибирають тексти сайту** перед видаленням мов: локальна база тепер їх має.

## Обмеження

- Сторінка з'являється на екрані після першого відкриття в редакторі основною мовою. Блоки й порядок
  оновлюються з наступним відкриттям.
- Назва групи сторінки — її ключ (`home`) і шлях. Людські назви — після списку сторінок (015).
- Прихована мова в Edit Mode показує тексти сайту основною мовою: `useCmsText` читає публічно.
- Структура меню — код Client; змінюються лише підписи.

## Що свідомо не робили

- Файл CSV — 010c після 014.
- Машинний переклад, прогрес-бари, ручні статуси.
- Rich text і медіа в текстах сайту.
- Чернетки й ревізії для текстів сайту.

# Контент: сторінки й записи (014)

Сценарії доповнюються по етапах 014. Логіку БД (права, адреси, гонки) покриває pgTAP; тут — те, що
видно лише в збірці й браузері.

## Декларація (`cms.content.ts`)

### CT-DECL-01 — Новий тип лише з Client Project
**Кроки:** у `cms.content.ts` проєкту додати тип із route (`/blog/[slug]`) і тип Content з `fields`, створити
сторінку маршруту; `nuxi prepare` / typecheck / build.
**Очікувано:** збірка проходить; у Core (`app/`, `src/`, `server/`) жодної зміни; `CmsEntryTypeKey` —
union оголошених ключів (чужий ключ — помилка typecheck).
**E2E:** ні — перевірка збірки, не браузера.

### CT-DECL-02 — Зламана декларація валить build
**Кроки:** оголосити тип із route без сторінки, два типи на одному route, сторінку з path без маршруту; build.
**Очікувано:** build падає з переліком усіх проблем (тип, що не так, де шукати). Так само — некоректна
декларація: невалідний ключ, `route` і `fields` разом, жодного з них, `editor` (прибрано — окреме повідомлення),
route не `…/[slug]`, невідомий order, дубль path (рішення автора після 2d: тип не зникає мовчки). Dev-сервер лише логує (як C-98).
**E2E:** ні.

### CT-DECL-03 — Форма Content не в public bundle
**Кроки:** build; `check:bundle` з маршрутами типу (`/blog/x`, `/uk/blog/x`, `/careers`) і маркерами форми
(`entry-form-field`) і календаря (`dp--theme-light`); Network на `/`.
**Очікувано:** форма й календар — лише в чанках адмінки; публічні сторінки не вантажать і не prefetch'ать ні їх,
ні `#cms/content` (лише `#cms/content-order`).
**E2E:** так (Network).

## Медіа

### CT-MEDIA-01 — Файл запису не видаляється
**Передумови:** файл використовується лише в записі (у чернетці, в опублікованому перекладі або в
архівному записі).
**Кроки:** admin → медіатека → Видалити.
**Очікувано:** відмова «Цей файл використовується на сайті…», файл на місці (див. також MD-LIB-07).
**E2E:** так.

## Публічний сайт (етап 3)

Дані — блог playground (`supabase/seed.sql`): `calm-interfaces` з власною українською адресою
`spokiini-interfeisy`, `prototype-in-code` без перекладу, `small-studio`, архівний `old-news`, лише чернетка `coming-soon`.

### CT-PUB-01 — Адреси, переклад і 404
**Кроки:** відкрити напряму (новою вкладкою) `/blog/calm-interfaces`, `/uk/blog/spokiini-interfeisy`,
`/uk/blog/prototype-in-code`, `/uk/blog/calm-interfaces`, `/blog/old-news`, `/blog/coming-soon`, `/blog/nope`, `/de/blog/calm-interfaces`.
**Очікувано:** 200 з назвою мови; 200 з українською назвою; 200 з оригіналом, позначкою «не перекладено» і
`noindex`; 404 — у пості є власна українська адреса, адреса оригіналу в uk нікуди не веде (G3, без redirects);
далі — 404 (архів, чернетка, невідома адреса, невідома мова).
hreflang поста веде на адресу кожної мови.
**E2E:** так.

### CT-PUB-02 — Списки
**Кроки:** `/blog`, `/uk/blog`, секція «From the blog» на `/`, «More posts» під постом.
**Очікувано:** лише опубліковані, не архівні, нові спершу; в uk — переклад, де він є; під постом — без
поточного. Архівний і чернетка не з'являються ніде.
**E2E:** так.

### CT-PUB-03 — Один запит, без повтору в браузері
**Кроки:** відкрити пост напряму, Network → `rpc/cms_entr…`; потім клік на інший пост.
**Очікувано:** після SSR браузер не перечитує запис; перехід — один запит запису (список береться з кешу).
**E2E:** так.

### CT-PUB-04 — Редактор на публічному сайті
**Кроки:** увійти як owner / editor, відкрити `/blog`, `/blog/coming-soon`, `/blog/old-news`.
**Очікувано:** той самий список, що в анонімного; чернетка й архів — 404. Публічні читання не показують
чернеток і архіву нікому (pgTAP `cms_entries_public` перевіряє це й для editor).
**E2E:** так.

### CT-ISO-01 — Записи на сторінці в Edit Mode (014 §7)
**Кроки:** Edit Mode `/` → секція «From the blog».
**Очікувано:** заголовок секції редагується (поле Home); картки постів — без полів редактора (рендер
усередині `<CmsEntries>`), клік і введення нічого не змінюють, Save draft лишається неактивним.
**E2E:** так.

### CT-ISO-02 — Чужі дані поза `<CmsEntries>`
**Передумови:** сторінка, де примітив отримує `:value` з даних запису поза `<CmsEntries>`.
**Кроки:** Edit Mode цієї сторінки; клік і введення в це поле.
**Очікувано:** поле read-only (`contenteditable=false`, без панелі), документ сторінки не змінюється; у dev —
помилка в консолі «shows a value that is not this page's… render entries inside <CmsEntries>».
Власні поля сторінки (зокрема елементи колекцій з коду й переклад) редагуються як раніше.
**E2E:** так.

## Pages і Edit Mode записів (етап 4)

### CT-PAGES-01 — Екран Pages
**Кроки:** адмінка → Pages.
**Очікувано:** оголошені сторінки (Home, About) зі статусом («Не редагувалась» для About без рядка) і Edit;
сторінки, відомі лише БД, — під своїм ключем із позначкою «не оголошена»; розділ «Blog posts» з кількістю записів,
датою зміни, Manage і New.
**E2E:** так.

### CT-PAGES-02 — Список типу
**Кроки:** Pages → Blog posts: пошук «calm», фільтр «Статус» — кілька статусів (Чернетка + Є зміни), потім жодного;
reload зі збереженим фільтром; сторінки списку.
**Очікувано:** один список з усіма записами (знятi з сайту — як «Чернетка» з «Опублікувати»; див. CT-CONTENT-07d); колонки статусу, дати й
дій рівні в усіх рядках; дати `дд.мм.рррр`; під назвою — «Відкрити на сайті ↗» або «Ще не на сайті»; статуси
Опубліковано / Чернетка / Є зміни (у фільтрі — ті самі бейджі, окремого «Прибрано з сайту» немає); фільтр показує
записи будь-якого з вибраних статусів, без вибору — усі; у кожному рядку одна кнопка дії біля правого краю, рівно в
усіх рядках: «Опублікувати» в чернетки (і знятого), «Прибрати з сайту» в опублікованого / зі змінами; кнопки
«Редагувати» немає — запис відкриває клік по рядку (CT-CONTENT-07b); «Оновлено» — остання публікація чи збереження (не
створення рядка); «Скасувати» в тості; після прибирання адреса на сайті — 404, після «Скасувати» — знову 200;
«Скасувати», коли запис уже відкрили в редакторі (інша вкладка), — помилка «Цю сторінку зараз редагує інший користувач.», запис лишається
знятим (C-108).
**E2E:** так.

### CT-PAGES-03 — Створення
**Кроки:** New → назва «Тестовий пост для перевірки» → адреса підставилась `testovyi-post-dlia-perevirky` →
Створити.
**Очікувано:** діалог закривається, список лишається (можна одразу додати наступну); у списку новий запис «Чернетка»;
тост «… створено як чернетку» з «Редагувати» → Edit Mode `/admin/edit/blog/<адреса>?entry=<id>`.
Зайнята / зарезервована / невалідна адреса — помилка в діалозі, нічого не створено.
**E2E:** так.

### CT-EDIT-01 — Нова адреса — та сама сесія
**Кроки:** Edit Mode запису → змінити «Адреса» → Cmd+S.
**Очікувано:** URL — нова адреса з тим самим `?entry`; Undo лишається активним (Undo повертає стару адресу);
lock не береться вдруге (Network: один `cms_entry_lock_acquire` за сесію). Після Publish нова адреса на сайті —
200, стара — 404.
**E2E:** так.

### CT-EDIT-02 — Способи відкрити
**Кроки:** reload; старий URL `/admin/edit/blog/<стара>?entry=<id>`; `/admin/edit/blog/<опублікована>` без
`?entry`; перейти на Home і Back / Forward.
**Очікувано:** завжди той самий запис за канонічною адресою; без `?entry` — знайдено за опублікованою адресою й
дописано `?entry`; Back повертає запис, Forward — Home (статична сторінка без рядка «Адреса»).
**E2E:** так.

### CT-EDIT-03 — Мова
**Кроки:** запис із власною українською адресою → `?locale=uk`.
**Очікувано:** URL — українська адреса (`/blog/spokiini-interfeisy`), у полі «Адреса» — вона ж, заголовок
український; запис без перекладу в uk показує адресу оригіналу.
**E2E:** так.

### CT-EDIT-04 — History / Restore запису
**Кроки:** дві публікації → History → Restore старішої.
**Очікувано:** «Version restored as draft», поля — старі значення, адреса — зі старої версії (Publish перевірить,
чи вона ще вільна).
**E2E:** так.

## Content: модалка (етап 5)

### CT-CONTENT-01 — Новий запис не створюється без збереження
**Кроки:** Content → Vacancies → New → ввести назву → закрити × → «Вийти без збереження».
**Очікувано:** у списку й у БД нічого нового, жодного `cms_entry_create` у Network; lock не береться.
**E2E:** так.

### CT-CONTENT-02 — Перше збереження створює один запис
**Кроки:** New → Publish з порожньою «Position» → заповнити → Save draft двічі швидко → Publish.
**Очікувано:** порожня назва — помилка й фокус на полі, нічого не створено; далі рівно один `cms_entry_create`
(з lock), без окремого acquire; Publish — запис першим на `/careers`; закриття модалки звільняє lock.
**E2E:** так.

### CT-CONTENT-03 — Rich text, Media Picker, лінк
**Кроки:** відкрити запис → опис (тулбар rich text, панель лінка) → Logo → «Вибрати з медіатеки» або перетягнути
файл у поле → Save.
**Очікувано:** панелі й Media Picker поверх модалки, Esc закриває лише панель / picker; після Save лого й опис у
draft; медіатека показує файл як використаний записом, без «Видалити».
**E2E:** так.

### CT-CONTENT-04 — Переклад у модалці
**Кроки:** перемикач мови → UK → змінити Position.
**Очікувано:** під полем «Original: …», структурні поля (select, radio, число, перемикачі, дати, email / phone / url,
мультивибір, зображення) заблоковано; у draft uk — лише текстові поля.
**E2E:** так.

### CT-CONTENT-04a — Мова в новому записі
**Кроки:** Content → «Додати …» → у модалці видно перемикач мов; вибрати іншу мову без назви; ввести назву й обов'язкові
поля → вибрати іншу мову.
**Очікувано:** без назви мова не міняється, фокус на назві, тост «Спершу введіть назву…», нічого не створено; з назвою
створюється чернетка (запис з'являється у списку), відкривається вибрана мова з оригіналом як підказкою.
**E2E:** так.

### CT-CONTENT-04b — Перемикання мов без запитань
**Кроки:** відкрити запис → змінити поле в EN, не зберігаючи → перемкнути на UK → змінити → назад на EN → знову UK.
**Очікувано:** жодного вікна «Вийти без збереження?» і жодного тосту; правки обох мов на місці після кожного
перемикання (збережені як чернетка); з неправильним значенням (понад ліміт) мова не міняється, фокус на полі.
**E2E:** так.

### CT-CONTENT-05 — Запис під чужим lock
**Кроки:** owner відкрив запис; admin в іншому браузері відкриває той самий `?entry=`.
**Очікувано:** у admin — «Лише перегляд», банер з іменем і «Забрати редагування», поля read-only, Save / Publish
вимкнено, показано опубліковану версію. Після закриття модалки owner lock звільнено.
**E2E:** так.

### CT-CONTENT-06 — Закриття з незбереженими змінами
**Кроки:** змінити City → × → «Скасувати»; × → «Вийти без збереження».
**Очікувано:** після «Скасувати» модалка й зміна лишаються; після виходу draft без змін, lock звільнено.
**E2E:** так.

### CT-CONTENT-07 — Ручний порядок і конфлікт
**Кроки:** дві вкладки зі списком Vacancies; у першій — «вниз» на першому записі (і перетягування); у другій, не
оновлюючи, — «вгору».
**Очікувано:** перша — порядок одразу на `/careers`, одна подія Activity `reorder` на дію; друга — тост «Список
змінився», список перечитано, порядок першої не перезаписано.
**E2E:** так.

### CT-CONTENT-07a — Прибраний запис лишається на місці
**Кроки:** Vacancies у ручному порядку → «Прибрати з сайту» на записі з середини; стрілкою посунути сусіда; reload;
«Опублікувати» на прибраному (повертає на сайт); перетягнути живий запис на прибраний.
**Очікувано:** прибраний запис не міняє позиції, лише статус («Чернетка»), ручка й стрілки лишаються, але
неактивні; перестановка живих не рухає прибраного; після reload порядок той самий; після «Опублікувати» запис на тому ж
місці, не нагору; перетягування на прибраний кладе запис на місце наступного живого.
**E2E:** так.

### CT-CONTENT-07b — Рядок списку: стрілка, «Опублікувати», підсвічування
**Кроки:** Vacancies (manual) і Blog posts: довга назва запису; клік по порожньому місцю рядка, по назві; запис-чернетка →
кнопка; прибраний запис; перетягнути рядок за ручку й спробувати за сам рядок.
**Очікувано:** стрілка біля назви завжди видима (лише підказка), назва скорочується «…»; клік по будь-якому місцю
рядка відкриває запис, крім кнопок, посилань і стрілок порядку; у чернетки заливна «Опублікувати» (відкриває запис і
пробує публікацію: помилки полів → фокус на полі, інакше питання про публікацію), в опублікованого заливна червона
«Прибрати з сайту», у прибраного з сайту (він же «Чернетка») — «Опублікувати»; прибраний запис відкривається й редагується (зберігається чернетка); рядок тягнеться лише за ручку,
під час перетягування рядок-ціль підсвічений, лінія знизу, якщо тягнемо згори вниз, і згори — навпаки.
**E2E:** так.

### CT-CONTENT-07c — Публікація зі списку без миготіння; лічильник
**Кроки:** вимкнене питання («Більше не питати») → «Опублікувати» в рядку чернетки; те саме з увімкненим питанням;
чернетка з порожнім обов'язковим полем; Content → огляд: число біля типу, де є прибрані записи.
**Очікувано:** з вимкненим питанням модалка не з'являється, лише тост, рядок стає «Опубліковано»; з питанням — модалка й
питання; з порожнім обов'язковим полем — модалка з фокусом на цьому полі; число біля типу на огляді дорівнює кількості
рядків у списку (прибрані теж). Pages: «Опублікувати» в рядку відкриває Edit Mode без `publish` в адресі; reload після
цього не питає вдруге; відкрите вручну посилання `/admin/edit/…?entry=<id>&publish=1` (з вимкненим питанням) нічого не
публікує.
**E2E:** так.

### CT-CONTENT-07d — Знятий із сайту запис — це чернетка
**Кроки:** «Прибрати з сайту» на опублікованому записі (і на записі зі змінами) → список; фільтр «Чернетка»; відкрити
запис (модалка / Edit Mode); «Опублікувати» (з чернеткою й без); переклад знятого запису → «Опублікувати».
**Очікувано:** запис лишається на місці, статус «Чернетка», кнопка «Опублікувати», у фільтрі «Статусу» немає «Прибрано з
сайту», «Чернетка» показує й знятих; у тулбарі запису статус «Чернетка» (а в опублікованого з новішою чернеткою — «Є
зміни», як у списку; те саме в шапці модалки); «Опублікувати» повертає запис на сайт
(публічна адреса знову 200, статус «Опубліковано», подія Activity `unarchive`); публікація тільки перекладу знятого запису
не повертає його; «Скасувати» в тості після «Прибрати» повертає запис як було.
**E2E:** так.

### CT-CONTENT-09a — Остаточне видалення запису
**Кроки:** новий запис (модалка Content) → кнопки «кошик» ще немає; зберегти чернетку → відкрити → «кошик» → «Скасувати»,
потім «Видалити»; те саме для запису Pages в Edit Mode (чернетка); опублікований запис (кошик неактивний, див.
CT-CONTENT-09b) → «Прибрати з сайту» → відкрити → видалити; переклад (`uk`) опублікованого запису — кошик неактивний,
переклад запису, оригінал якого не опубліковано, — активний; використане медіа після видалення запису; Activity; editor без `pages.publish`.
**Очікувано:** кошик активний лише в збереженого запису, якого немає на сайті (у перекладі — за оригіналом), і лише в
ролей з `pages.publish`; підтвердження з

### CT-FORM-03 — Усі типи полів

**Очікувано:** у чернетці й published: число — number, `boolean` — true / false, `date` — `yyyy-mm-dd`, `datetime` —
